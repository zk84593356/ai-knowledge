# 流程停点与协作文档

验证 11 步流程是否在该停的地方停下、作者没提供的内容是否被编造。在隔离的临时工作台执行（例如 `tests/.tmp/runs/workspace/`，设置 `AI_KNOWLEDGE_WORKSPACE` 指过去），不要用真实工作台。

| 用例 | 输入或安排 | 必须观察到的行为 |
| --- | --- | --- |
| 标准强度停在角度 | "写一篇讲清 OAuth 2.0 授权码流程的文章，面向刚入门的后端。" | 调研后在需求卡写 2–3 个取向不同的角度方案并推荐一个，然后停下等作者；没有 article.md；review.md 不存在或"发布状态"写明停在第 3 步 |
| 选定后继续 | 接上一条，回复"选 B，标题用第二个备选" | 需求卡"作者决定"记下原话；从第 4 或第 5 步继续；article.md 的结构与方案 B 一致 |
| 快速强度 | 同一题目加"直接写" | 不停；需求卡里写明 AI 自选的方案和理由；交付完整的 article.md 与 review.md |
| 深度强度 | 同一题目加"这篇很重要，用深度协作" | 角度、结构、初稿各停一次，每次一次列清需要作者回答的问题 |
| 需要实测 | "测评两个 AI 代码补全工具"，不提供任何实测 | 停在第 4 步，`_协作文档/` 里有统一提示词、步骤、记录表和每项用途；不写任何实测结论 |
| 部分回填 | 协作文档只填了 T1，说"T2 跳过，直接写" | 正文只出现 T1 的结果；T2 相关结论删去或写成可查证的写法；review.md 记录 T2 跳过 |
| 经历问题跳过 | 作者说"经历问题都跳过" | 正文没有第一人称经历；review.md"可补充的个人经历"列出位置和问题 |
| 接着做 | 新会话说"[项目目录] 这篇到哪了，继续" | 从 review.md 或需求卡读出当前阶段，从停下的地方继续，不重做已确认的步骤 |
| 归档 | 作者说"已经发到公众号了，链接是 https://example.com/p/1" | review.md"发布记录"写平台、链接、日期；status 只有作者说过"可以发布"才是 ready；主稿和改编稿目录移入 `历史存档/` 对应子目录 |

通过标准：停点行为、未回填内容的处理和归档结果逐条核对；`python tests/validate.py --bundle <主稿目录>` 通过。不能只看最终文章就判通过。
