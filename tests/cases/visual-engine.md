# 图文验收用例

## 实际主案例

输入："什么是 SSO？用 `<brand-id>` 品牌做封面和解释图；介绍卡只用确认身份。"

品牌从内容工作台（`AI_KNOWLEDGE_WORKSPACE` 或 `~/.ai-knowledge/settings.json` 记录的位置）的 `品牌资产/<brand-id>/brand-kit.json` 读取；没有点名时先列出已确认品牌问作者，没有品牌时用通用图解。复跑时可把 `AI_KNOWLEDGE_WORKSPACE` 指向合成的 `tests/fixtures/workspace-demo`，品牌用 `demo-brand`。

读取当前 Skill、视觉规划与视觉加载指南，再读取选中 kit。输出到独立主题目录：`article.md`、`review.md`、`assets/`。默认 1 张封面 + 2–4 张解释图；文章只嵌 PNG/JPEG，SVG 作为可编辑源登记在 `assets/manifest.json`。不覆盖 canonical 素材，也不再单独产出 visual-plan.md，配图计划写在 review.md 的"配图"一节。实际工具可用时生成角色场景；工具不可用时在"配图"一节明确写待制作项和原因。

验收：标题/条件/箭头正确；默认文风继续有效；全套生成图保持 generated 或 draft，未经用户确认不升级 approved；介绍卡不导入草案职业或 CTA；图片相对路径随目录迁移仍有效。实际成果见 `examples/concept-sso/`。

## 其他模式与边界

| 输入 | 应观察的行为 | 验证方式 |
| --- | --- | --- |
| 复盘（功能）的 OIDC 演示，默认配图 | 不读品牌图片也能做通用解释图；保留适配器未实现/未真实登录 | `examples/feature-oidc-demo` 与代码测试回归、内容审读 |
| 复盘（故障）的 Pages 模拟记录，要证据图 | 以已有日志为依据；无截图不造 UI，不画"部署成功" | 案例重跑与视觉选择走查 |
| 用户说"不要图" | 不建 assets/、不读品牌；review.md 写明不配图的原因 | 无图主题自动测试 + 指令走查 |
| 不用品牌，仍用个人文风 | 通用图解和个人写作规则可同时存在 | 路由测试 + 指令走查 |
| 指定其他完整 kit | 替换工作台品牌，版本与素材 ID 对齐；指定目录读不到时回退通用图解，不换用其他配置 | 路由/一致性测试 |
| 没有工作台、没有品牌、kit 缺失或坏 JSON | 降级通用图解；文章与核验记录继续 | 负向输入 |
| `AI_KNOWLEDGE_WORKSPACE` 指向不存在的目录 | 说明原因并用通用图解，不改读 settings.json 记录的工作台 | 路由测试 |
| 工作台有两个已确认品牌，请求没点名 | 第 3 步确认角度时问用哪个或不用，答案写进需求卡"配图品牌"；不自动挑 | 路由测试 + 流程走查 |
| 只要配图计划 | 在 review.md"配图"一节列出计划，没有额外生图调用 | Agent 流程审读，不假装脚本执行过模型 |
| 没有生图工具 | 计划 + 可编辑图解 + 人物待制作项 | 规则走查，当前环境有工具未模拟不可用宿主 |
| 图片未制作、损坏、越界、临时 URL 或 SVG 直接嵌入文章 | 不嵌入或检查失败 | 负向测试 |
| 原素材未获公开分发许可 | 本地交付可以；不自动推送 | 台账和 Git 状态 |
| 自动检查通过但用户未批准 | 不升级 approved | 状态负向测试 |
| 迁移主题目录到其他位置 | 图片解析不依赖 Skill 原路径 | 独立目录测试 |
| 想生成统计图但没有数据 | 不造数据，必要时单独明确模拟 | 内容审读 |
| 品牌有视觉语言，生图工具能接收参考图 | 写一份出图说明，附母版；全套图用同一材质、线条、主色用法、签名图形和版式标记；角色在知识图里做与内容相关的动作 | 整组拼图审读 + 角色清单逐条记录 |
| 生成图里有中文标题和标签 | 放大逐字核对；错字就重做，最多 3 次，仍错改为程序排字；不声称"文字全对"而不逐字看 | 看图记录每张的核对结果 |
| 生成的数据图 | 量柱高或扇区，与真实比例偏差超过最大值 3 个百分点时不能发布，改为程序画数据部分 | 实测比例写进 review.md |
| 建立品牌或改视觉语言 | 起草视觉语言提案，做四图测试并做遮名检查；用户满意才登记 `role: sample` 的风格样板 | 流程走查 + `kit` 检查 |
| 用户给了别人的作品当审美参考 | 只学方法和检查方式；不复制角色、配色组合、版式、签名图形和提示词原文，不把别人的图传给生图工具 | 出图说明审读 |

自动脚本不验证角色像不像、事实是否正确或人类是否喜欢；这些按视觉清单逐项记录。此表是复跑用例，不表示所有宿主均已实际执行。

## BKC-01～05 合并后的三模式与边界回归

本节是内容行为判据，不通过匹配规范关键词判断通过。实际执行方式及限制写入 RESULTS；自动测试只检查文件/状态兼容，不能证明 Agent 的设计选择。

| 模式/输入 | 需要观察的选择与边界 |
| --- | --- |
| 复盘（功能）：用现有 OIDC 演示解释"回调为什么不能直接相信"，只做配图计划 | 新手可先理清浏览器/应用/适配器关系，再决定是否需要时序；不能套 OA/CRM 两阶段或声称已有验签。不得生成额外图或改文章 |
| 讲解：复核 SSO 解释与图解，保持文章不变 | 关系先于深入步骤适合本例；容器 390、内边距各 16 得图宽 358，关键条件仍在正文；不将本例尺寸设为全局要求 |
| 复盘（故障）：Pages 模拟目录排查，读者已知参与者，只做计划 | 直接用路径对照/步骤或纯文字；不强制先画主体关系，不把模拟构建恢复画成部署成功 |
| 简短概念 / 用户说"不要图" | 文章与核验记录继续有效，允许零图，不读取品牌；不能为五条规范增加封面、署名或固定配图数量 |
| 只有一种字体或无渲染工具 | 记录可用字体和未验证范围，不能声称双字体/跨系统通过；不因此伪造导出文件 |
| 图片本身需要独立传播的状态标识 | 可在图片上保留合适标识，但文章正文不写草稿等状态字样；不把"默认不靠小字"解释为禁止水印或自动批准 |
| 复用图身份正确但动作不适合新主题 | 不强行贴标签冒充新动作/真实 UI；按母版制作待验收新版本，原图不覆盖 |
| 缺截图、数据、源码或公开许可 | 不造界面、数字、类名或授权结论；只交付可核实部分，待补项写进 review.md |

无图主题不要求台账、有图或有 assets/ 时必须有台账、文章只嵌 PNG/JPEG、SVG 只作可编辑源，由 test_visual_assets.py 用临时目录里新构造的主题自动复跑。图种选择和真实事实边界仍须读取案例和证据后审读；无真实模型宿主端到端或跨平台环境时如实注明。
