# 运营沉淀：从发布数据里学到下一篇怎么写

第 11 步用，作者提供发布数据时才做。目的是让下一次选题和写作更好，而不是解释某一篇为什么“爆”或“扑”。

## 记什么

作者提供数据后，在主稿目录（发布后在 `历史存档/` 里）新建 `数据复盘.md`，一个平台一张表：

| 时间点 | 指标（后台名称） | 数值 | 备注 |
| --- | --- | --- | --- |
| 发布后 24 小时 | | | |
| 发布后 72 小时 | | | |
| 发布后 7 天 | | | |

同时记下：发布时间、标题、封面、平台、有没有收到违规通知或被加标识。

指标只写后台里显示的名称和数值，不自己编计算公式。各平台常见的指标（名称和口径以后台说明为准）：

| 平台 | 常见指标 |
| --- | --- |
| 公众号 | 阅读次数和阅读人数、分享、收藏、“阅读原文”点击 |
| 小红书 | 观看量、点击率、人均观看时长、互动（创作中心 → 数据中心） |
| 抖音 | 播放量、完播率、5 秒完播率、平均播放时长 |
| B站 | 播放、平均播放进度、游客占比、单稿件涨粉、粉丝活跃时间 |

## 怎么比

以下是复盘方法，不是平台规则：

- **固定时间点**：每篇都在发布后 24 小时、72 小时、7 天采集，比较才有意义。
- **只比同类**：同平台、同形式、相近时长和同类选题放在一起比。
- **一次只看一个变量**：想知道标题的影响，就让选题、封面、发布时间尽量不变。现实中很难完全做到，比较时写清哪些条件不同。
- **比率和绝对值一起看**：曝光差几倍时，比率没有可比性。
- **先排除违规因素**：有违规通知、被限制或被加标识时，先处理这件事，再分析内容本身。
- **样本够了再下结论**：单篇的异常值只记录、不下结论；同类内容积累到 5–10 篇（经验值）再看趋势。

## 写成结论

结论写成可以检验的假设，带上证据和样本：

> 候选：公众号的问题型标题比结果型标题阅读人数高（同类讲解文 6 篇，问题型 3 篇均高于结果型 3 篇；选题难度不同，待更多样本）。

- 单篇数据只能得出“候选”结论；有了足够同类样本，作者确认后才算“确认”。
- 不把相关写成因果：“这篇数据好，是因为标题好”通常无法证明。
- 不根据传言调整（例如“某个词会被限流”），除非有平台规则支持（见 [防限流指南](自媒体防限流指南.md)）。

## 写回哪里

| 结论类型 | 写回 |
| --- | --- |
| 选题方向（哪类主题读者更关心） | `我的项目/_briefs/选题库.md` |
| 标题、开头、结构的写法 | 作者确认后，按 Skill 的「风格写回」进入个人写作规则 |
| 平台规律（发布时间、封面形式） | 工作台 `规范指南/运营沉淀.md`，由作者维护 |

ai-knowledge Skill 只提出候选结论和写回位置，作者确认后才写入；不自动修改作者的规范指南和写作规则。
