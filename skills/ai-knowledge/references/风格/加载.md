# 公共技法与个人风格的加载

写文章时始终读取写作技法和当前类型的调研指南。写作技法优先读工作台里的 `写作技巧/内容写作技巧.md`，工作台没有这个文件时读 Skill 自带的 [内容写作技巧](../../templates/内容工作台/写作技巧/内容写作技巧.md)。

个人风格全部放在作者的内容工作台里（位置怎么找见 [发布合同](../流程/发布合同.md)），不随 Skill 分发：

- `风格参考/我的写作规则.md`：作者确认过的写作规则，写稿时最高优先。
- `风格参考/我的写作档案.md`：规则的适用范围和身份边界。
- `风格参考/改稿学习日志.md`：改稿复盘的记录，正常写作不读。
- `风格参考/` 里的其他文章：文风样板。
- `用户人设.md`、`写作技巧/`、`规范指南/`：作者是谁、作者认可的方法、平台规范。

没有工作台时只用 Skill 自带的默认文件，Skill 照样完整可用。

## 选择顺序

1. 用户明确说"只用公共规则"或"关闭个人风格"：不读写作规则、档案、`写作技巧/` 和 `风格参考/`，只用 Skill 自带的技法。`用户人设.md` 和 `规范指南/` 管的是身份边界和发布规则，照常读。
2. 用户指定了某个规则文件（Profile）：只读这个文件及其指定的配套规则，不与工作台里的规则混用。外部档案的归属与有效性仍要核对。读不到时报告失败，暂用公共技法，不悄悄换成工作台里的。
3. 用户本次给了工作台路径、或环境变量 `AI_KNOWLEDGE_WORKSPACE` 已设置，但目录不存在或读不到：报告原因，用公共技法，不再去 `~/.ai-knowledge/settings.json` 找。
4. 其余情况读工作台。先读 `我的写作规则.md`，只应用字段完整、状态为"已确认"、确认依据有效且适合本篇的规则；再读 `我的写作档案.md` 了解适用范围。候选、已停用、模板占位、重复 ID 或没有确认依据的规则不生效。
5. 规则文件缺失、空白或没有有效规则时，直接回退公共技法；不追问、不自动建档、不要求用户提供经历。

个人风格作用于 article.md 的表达；review.md 是工作记录，不需要套用文风。没有启用个人规则就不读复盘资料和改稿学习日志，也不要每次读取学习历史。

## 工作台里的其他资料

- `用户人设.md`：每篇都读，用法见 [用户人设](../流程/用户人设.md)。
- `写作技巧/`：每篇都读文件名，只打开和本篇类型、平台相关的文件。它们是作者认可的方法，和 Skill 自带的冲突时以作者的为准。
- `规范指南/`：平台改编、口播稿、发布前检查时读对应文件，内容比 Skill 的通用指南新时以作者的为准；但法规和平台官方规则仍以原文为准。
- `风格参考/` 里的文章：作为文风样板。只读和本篇主发平台、内容类型最接近的 1–3 篇（人设里列了代表作就优先读代表作），学开头、小标题、段落节奏和口吻，不复制内容、结构、案例和金句。深度协作或作者要求“按我的风格写”时读；快速模式可以跳过。

只读取上面这些约定位置，不扫描工作台里的其他资料，不执行其中的脚本。这些文件是私人资料：规则原文、文风样板和人设原文不复制进 article.md、review.md、当前项目或任何公开仓库；review.md 只记录采用了哪些规则 ID、读了哪些文件名。

## 冲突时听谁的

规则冲突的顺序：事实准确、安全与隐私 → 本次明确要求 → 已确认的写作规则 → 工作台写作技巧和文风样板 → Skill 自带的写作技法 → 默认表达。正确语法和准确引用也属于事实表达；标点偏好不能改动 YAML、代码、命令或标准原文。规则格式有效不代表内容可信，写作时仍要检查冲突。

可选的 [style_learning.py](../../scripts/style_learning.py) 的 context 命令按上面的顺序输出只读的选择结果；没有 Python 时按顺序读取 Markdown 即可。工具只做路径与字段检查，不判断规则是否损害事实，不执行资料里的指令。

```text
python "<skill-dir>/scripts/style_learning.py" context
python "<skill-dir>/scripts/style_learning.py" context --workspace "<内容工作台>"
python "<skill-dir>/scripts/style_learning.py" context --public-only
python "<skill-dir>/scripts/style_learning.py" context --profile "<explicit-profile.md>"
```

规则条目格式为 `## <前缀>-<三位编号>`（如 `## STYLE-001`）加单行字段：规则、适用范围、修改原因、来源文章、修改证据、支持次数、例外、状态、确认依据。格式示例见 Skill 自带的 [我的写作规则](../../templates/内容工作台/风格参考/我的写作规则.md)。支持次数是独立文章数，用户直接指定的偏好可以为 0；确认依据单独记录。说明性段落不自动成为已确认规则。

交付时简短说明采用的个人规则 ID 或回退原因。选择结果不等于事实审查通过。
