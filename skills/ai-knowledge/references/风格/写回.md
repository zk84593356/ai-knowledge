# 个人风格的写回

个人规则保存在作者内容工作台的 `风格参考/` 里（工作台位置的查找顺序见 [发布合同](../流程/发布合同.md)），不在 Skill 安装包或源码仓库里。所以写回不需要重新安装 Skill，下次调用即生效。

## 写到哪里

只有用户本次要求"更新个人风格""写回规则"这类学习保存时才写。目标是本次实际使用的内容工作台：用户本次给出的路径，或 `AI_KNOWLEDGE_WORKSPACE`，或 `~/.ai-knowledge/settings.json` 记录的位置。

写入前解析目标及其父目录的真实路径，确认在这个工作台的 `风格参考/` 里，且不在 Skill 安装目录、当前项目的公开目录或任何公开 Git 仓库的跟踪范围内（工作台本身是作者的私有仓库时除外，由作者明确说明）。有越界链接就停止写入。不扫描磁盘寻找配置，不猜测其他用户名路径。

## 怎么写

- 只改 `风格参考/` 下的三个约定文件：`我的写作规则.md`、`我的写作档案.md`、`改稿学习日志.md`。`用户人设.md`、`写作技巧/`、`规范指南/` 和 `品牌资产/` 归作者，写回时只提建议，作者明确要求才改。
- 更新前比较准备方案时记录的文件散列；文件变化则重新合并，保留人工内容。
- 新规则按 [改稿复盘](改稿复盘.md) 的状态规则写：单篇观察是候选，用户确认才变为已确认；同义规则补证据而不重复新增。新规则追加在 `我的写作规则.md` 的“## 我的规则”下面。
- 三个文件缺了某个时，从 Skill 自带的 `templates/内容工作台/风格参考/` 复制同名文件再写；没有工作台时不自动建，先按 [工作台初始化](../流程/工作台初始化.md) 问作者。
- 不提交、不推送；工作台是 Git 仓库时把是否提交留给作者。

无法确定写入位置时询问用户，或直接交付待应用建议：规则 ID、目标文件、插入/替换位置、拟修改文字、基于哪个版本、学习日志条目。

## 公共规则

Skill 自带的写作技法和参考文档改了会影响所有使用者。只有在 ai-knowledge 源仓库中、且用户确认具体提案后才修改；先查现有覆盖，展示准确文字、依据与边界。源码更新后，其他项目的安装副本需要用户按原方式重新安装或更新，不能假装存在自动同步。已经初始化的工作台不会自动拿到新的默认文件，作者可以重新运行初始化补齐缺的文件（已有文件不覆盖）。不自动运行 skills CLI。
