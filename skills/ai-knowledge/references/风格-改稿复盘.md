# Style Reflection：从实际改稿中学习

仅在用户要求复盘、学习文章修改或更新风格时加载。只做复盘时交付一份学习报告，不生成文章，不重新实现 [Style Analyzer](风格-分析.md)。

## 找到真实比较对象

确认 AI 初稿、用户指定的满意终稿、文章 ID/主题及编辑归属。优先使用用户给出的文件、当前对话明确的版本或可验证 Git 内容；多个可能终稿时询问具体版本，不能按最近修改时间猜“用户已认可”。记录两版散列与行号，完整阅读再比较。

仅终稿：可以观察表达特点，报告“未提供初稿”，不生成删除/替换故事，不把满意终稿的每个特点都推定为修改习惯。未确认终稿：可以比较，但不据此升级个人规则。演示稿只能产生演示结果，不计入作者真实习惯的支持数。

可选 [style_learning.py](../scripts/style_learning.py) compare 命令输出实际行级差异和散列；没有 Python 可用宿主 diff 或逐段对照。它不分类目的、不改任何文件、不上传原文。报告可能含私人片段，默认留在会话/用户指定的私人报告位置，不直接入公开仓库。

```text
python "<skill-dir>/scripts/style_learning.py" compare --draft "<draft.md>" --final "<final.md>"
python "<skill-dir>/scripts/style_learning.py" compare --final "<final.md>"
```

## 从变化到候选

逐段区分事实修正、增加证据、面向读者的解释、删重复、语气/节奏、排版、错字。只有确实发生的文字变化才列作修改证据。编辑目的未由用户说明时标“推断”，列其他合理解释，例如因为本篇篇幅限制而删段，不一定意味着永远拒绝展开。

每个候选记录：稳定 ID、规则描述、适用范围、修改原因、来源文章、具体前后证据（必要的短片段或私人定位）、支持次数、例外、状态。状态仅为候选/已确认/已停用，确认依据另列。用 [学习报告模板](../templates/改稿复盘-template.md) 交付。

先按“意图 + 范围 + 例外”对照现有规则。已有同义规则就补证据，不新建换词副本；有冲突先记录待解决，不覆盖。稳定 ID 一经分配不重用；修改与停用保留原 ID 和历史原因。

同篇多处修改只计一个支持文章，同一文章重复复盘不再加次数；多版改稿也不伪装新文章。不同文件名但相同内容先判重复。脚本的 add_evidence 仅做精确记录去重，语义合并须由 Agent 检查。不得用散列或次数自动确认永久习惯。

单篇默认候选；多篇重复可以提高可信度，但仍需用户明确确认“将这条作为以后偏好”。确认文章满意不等于确认提炼出的全部永久规则。用户直接指定习惯可以立即记已确认，确认依据记录实际请求，不伪造支持文章。

## 决定是否写入

“只分析/只生成报告”优先：不改 profile、rules、learning-log 或公共指南；在报告中列建议。

用户要求“学习并更新个人风格”时，可写候选及学习记录；已经由用户明确确认的偏好可写已确认。不能把演示修改升级为真实习惯。永久档案保存最少必要证据：文章代号、公开安全的定位或摘要；私人原文、真实身份、客户、地址、凭据、完整参考提示词不写入公开目录。不能确认可公开时，将原始证据保留私人位置，公开日志仅记去标识概括，或只交付建议。

写入位置按 [个人风格写回](风格-写回.md) 判断：个人规则写到个人配置目录，不写进 Skill 或公开仓库。生成报告前后重新读取现有的 profile、rules 和 learning-log，防止覆盖用户并行修改；只编辑对应条目和追加一条有意义的日志，不重写整份档案。相同版本重复学习没有新证据或状态变化时是 no-op，报告已记录，不无限追加日志。写入失败报告哪些文件已改、哪些未改，不宣称完整成功。

## 公共规则候选

先检索 [写作技法](内容写作技巧.md)、[编辑与核验](打磨与核验.md) 和相关模式指南。已有覆盖标“已覆盖”，不重复提议。个人称呼、口头禅、私密经历、未验证偏好不提升为公共规则。

未覆盖且跨主题有解释价值时，提出：目标文件和位置、拟增加/替换的准确文字、不同主题证据、适用边界、反例、预期收益、回归案例。单主题证据不足时列“待验证公共候选”。只展示草案，不写公共文件；用户对具体方案确认后才执行，确认授权只覆盖该方案。更新后记 CHANGELOG 并跑讲解、复盘等类型案例和边界回归。

## 最终报告

说明实际输入与缺失项、确认来源、差异、推断目的、去重/冲突、候选/确认/停用变化、公共候选及拟修改文本、实际改动路径、未写回原因。无法确定个人配置目录时可交付可应用的 Markdown 条目和插入位置，不伪造应用成功。不得自动 Git Commit、Push、安装、发布或双向同步。
