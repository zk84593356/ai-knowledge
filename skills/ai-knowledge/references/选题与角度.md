# 选题与角度：先想清楚这篇为什么值得读

同一个主题可以写成很多篇文章。角度决定写给谁、核心判断是什么、读者读完带走什么。调研完成后、动笔之前，给作者 2–3 个取向真正不同的方案，由作者选。

## 一个方案包含什么

写进需求卡的“角度方案”一节，每个方案都写全：

| 项 | 要求 |
| --- | --- |
| 核心判断 | 一句话：读者原来以为什么，其实是什么 |
| 写给谁 | 具体到处境，例如“刚接手登录模块的 Java 后端” |
| 标题 | 1 个主标题和 2 个备选，取向不同 |
| 结构 | 3–7 节，每节一句话写清回答什么问题 |
| 篇幅 | 预计字数和配图数 |
| 需要作者提供 | 实测、截图、经历，没有就写“无” |
| 难点与风险 | 证据不足的地方、可能引起争议的地方 |

最后写推荐哪一个，以及理由。

## 三个方案要真的不同

改一个词不算新方案。拉开差别的方式：

- **换读者**：给新手讲原理，还是给有经验的人讲坑。
- **换判断**：同一事实可以支撑不同判断，例如“这个工具适合个人”或“这个工具不适合团队”。
- **换形式**：讲解、复盘、测评、观点、清单、对比。
- **换切口**：从一个故障切入、从一个误解切入、从一个数字切入。

## 核心判断怎么找

核心判断是读者的预期和事实之间的差距。差距越具体、越出乎读者意料，文章越值得读。这和《让创意更有黏性》（Made to Stick）讲的“意外”原则一致：先打破读者原有的认识，再用正文把新的认识补上。心理学家 Loewenstein 的信息缺口理论也说明，人在意识到自己知道的和想知道的之间有缺口时，会产生好奇。

找差距的问题：

- 读者在这个主题上最常见的误解是什么？
- 调研里哪个发现让我自己意外？
- 官方文档没说、但实际会遇到的是什么？
- 大家都在说 A，有没有证据支持 B？

说不出核心判断，说明调研还没完成，回到第 2 步。

## 评估方案

按下面五项给每个方案打“高、中、低”，写在推荐理由里：

| 维度 | 问题 |
| --- | --- |
| 读者价值 | 读者读完能做成什么、少走什么弯路 |
| 作者优势 | 作者有没有别人没有的经历、实测或视角 |
| 证据充分 | 现有证据能不能撑住核心判断 |
| 差异 | 和已有的同主题文章比，新在哪里 |
| 时效与风险 | 会不会很快过时，会不会踩平台规则或引起不必要的争议 |

证据不足的方案可以推荐，但要写清“需要作者先完成某项实测”。

## 标题

每个方案的标题都围绕核心判断写，常用三种取向：

- **结果型**：读者能拿走什么。
- **问题型**：读者心里的疑问。
- **反差型**：纠正一个真实存在的误解。

标题承诺的内容，正文必须兑现。不用“震惊”“必看”“一文读懂全部”，也不用“最”“第一”这类绝对化用语（平台规则见 [防限流指南](自媒体防限流指南.md)）。

## 选题库

工作台里可以维护 `我的项目/_briefs/选题库.md`，一行一个选题：日期、选题、核心判断草稿、来源（读者提问、实测发现、复盘结论）、状态（待写、在写、已发、放弃）。没被选中的角度方案也记进来，以后可能用得上。[运营沉淀](运营沉淀.md) 得出的结论同样写回这里。
