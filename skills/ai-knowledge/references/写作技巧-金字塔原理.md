# 金字塔原理：先说结论，再分组讲理由

第 5 步搭结构时用。金字塔原理来自 Barbara Minto 在麦肯锡总结的写作方法（《金字塔原理》，The Minto Pyramid Principle）。核心是：读者一次只能记住有限的东西，所以先给最重要的结论，再分组给出支撑它的理由，每组下面再展开。

## 四条规则

中文资料常把它概括成 16 个字：结论先行、以上统下、归类分组、逻辑递进。这是国内培训资料的通行概括，不是原书的原话，但和原书的要求一致：

| 规则 | 意思 | 在文章里的样子 |
| --- | --- | --- |
| 结论先行 | 先说结论，再说理由 | 开头几段内给出核心判断 |
| 以上统下 | 上一层是下一层的总结 | 每节小标题能概括这一节；全部小标题连起来能推出核心判断 |
| 归类分组 | 同一组里的点是同一类 | 不把“原因”“步骤”“注意事项”混在一组里 |
| 逻辑递进 | 同一组的点按一种顺序排 | 时间顺序、结构顺序、重要性顺序，选一种 |

原书还要求横向的几点之间是演绎关系（大前提、小前提、结论）或归纳关系（几件同类事指向一个结论）。知识文章大多用归纳；需要证明一个判断时用演绎，但演绎链不要超过三步，读者会跟丢。

## 开头用 SCQA

原书建议用“情境、冲突、疑问、回答”组织开头：

- **S 情境**：读者认同的背景。“你照着文档配好了登录。”
- **C 冲突**：情境里出了什么问题。“上线后，安全扫描说回调有风险。”
- **Q 疑问**：冲突引出的问题。“明明能登录，风险在哪？”
- **A 回答**：核心判断。“回调里少校验了一个随机值，别人可以冒充你登录。”

国内资料还常整理出几种变体，按文章需要选：

| 变体 | 顺序 | 适合 |
| --- | --- | --- |
| 标准式 | S → C → A | 大多数讲解和复盘 |
| 开门见山式 | A → S → C | 结论本身就够吸引人，或读者很忙 |
| 突出忧虑式 | C → S → A | 读者正被这个问题困扰 |
| 突出信心式 | Q → S → C → A | 读者心里已经有明确的疑问 |

开头的 S 只写读者已经认同的事，不写读者不知道的背景；C 必须真实存在，不为制造冲突编问题。

## 搭结构的步骤

1. 写下核心判断（来自选定的角度方案）。
2. 站在读者的角度问：听到这个判断，他第一个会问什么？这个问题的答案就是第一节。
3. 继续问，直到读者没有重要的问题。一般得到 3–7 节，超过 7 节就把相近的合并。
4. 检查每一组：是不是同一类？按什么顺序排？
5. 每节第一句话写这一节的结论，后面是理由、例子或代码。

## 小标题

- 小标题写成判断或问题，不写话题。“state 防的是登录冒充”比“state 参数”好。
- 同一层的小标题句式一致，读者只看小标题也能知道全文在说什么。
- 需要编号时，可以用“一、二、三”或“1. 2. 3.”加判断句，例如“1. 回调里少一个校验，就能被冒充”。编号让读者知道一共有几点、读到第几点了。

## 写完自查

- 只读标题、开头和全部小标题，能不能复述出核心判断和主要理由？
- 删掉任意一节，核心判断还成立吗？还成立，说明这一节可能不必要。
- 有没有一节同时在回答两个问题？拆开或删掉一个。
- 每节第一句是不是结论？
