# 引导共写：作者出想法和判断，AI 追问、组织、解释、改稿

协作强度为“共写”时按本文执行。一句话需求写不出好文章，原因通常不在 AI，而在问题太模糊：AI 不知道作者为什么写、写给谁、自己怎么看。共写先把这些问出来，再和作者一节一节地把文章写出来。

## 分工

| 作者负责 | AI 负责 |
| --- | --- |
| 为什么写、写给谁 | 一次一个地追问，把模糊的想法问具体 |
| 自己的经历、困惑和判断 | 查证事实，补上作者不知道的部分 |
| 选角度、调顺序、勾选每节写什么 | 给出结构和每节的候选要点，说明为什么这样排 |
| 决定措辞和取舍 | 把作者的原话整理成通顺的段落，提供例子、类比和开头的候选 |
| 说“可以发布” | 改稿、读者测试、检查 AI 腔 |

AI 能提供候选，但不替作者做判断。经历、情绪和“对，就是这个”的选择只能来自作者；作者没说过的，不写成作者的话。

## 第一段：追问（第 1 步）

### 先看，再问

开口前先读已有的材料：需求卡、工作台的资料卡和选题库、作者给的文件或链接。能从材料里查到的不问。

### 怎么问

- **一次只问一个问题**，等作者回答再问下一个。问题接着作者上一句回答往下问，不照着清单念。
- 问得具体，并说明为什么问：“如果读者是刚接手登录模块的后端，我会从一次报错讲起；如果是产品经理，我会从用户体验讲起。这篇主要写给谁？”
- 作者答得含糊，追问一次具体的例子（“比如哪一次？”“当时看到了什么？”）。还是没有就记为“暂缺”，不逼第三次。
- 作者卡住时，给 2–3 个具体候选让他挑或改。作者说“你定”，就提一个具体方案，记为 AI 的建议。
- 作者说“够了”“直接写”，立刻停止追问，按已有信息进入下一步。

### 要问出来的东西

这是要覆盖的范围，不是问卷。一般 5–8 个问题，按作者的回答取舍：

1. **起因**：为什么现在想写？有没有一件具体的事，例如被问倒、踩了坑、看到一个误解？这常常就是开头。
2. **读者**：写给谁，他们现在卡在哪里？
3. **作者自己的困惑**：你第一次接触这个主题时，哪里没想明白？作者当时的困惑，往往就是读者现在的困惑。
4. **核心判断**：读完这篇，你最想让读者记住哪一句话？说得两边都对时，直接指出来：“这样说比较稳，但读者记不住。你更站哪一边？”
5. **素材**：有没有自己的经历、实测、截图、代码或数据？
6. **读完之后**：读者能做成什么，或者会改变什么做法？
7. **不写什么**：哪些内容这篇不讲？

不同内容类型侧重不同：

| 类型 | 多问什么 |
| --- | --- |
| 讲解 | 最常见的误解；作者自己卡住过的地方；读者已经会什么 |
| 复盘 | 当时发生了什么、当时怎么判断的、后来发现了什么 |
| 测评 | 拿来干什么、用什么标准比、哪里出乎意料 |
| 观点 | 主张是什么、最强的反对意见是什么、作者凭什么这样说 |

### 整理成访谈卡 ◆

问完后整理成访谈卡，写进需求卡的“访谈卡”一节（不另建文件）：

- **开头素材**：最适合放在开头的一件具体的事。
- **读者**：写给谁、卡在哪。
- **核心判断草稿**：一句话。
- **作者原话**：作者说过、可以直接用进文章的说法，逐字记录。
- **经历与素材**：作者能提供的东西，以及每项用在哪里。
- **困惑与误解**：作者自己的困惑、读者常见的误解。
- **不写什么**。
- **还缺什么**：需要调研补的事实、需要作者补的经历。

只记作者真的说过的话；AI 补充的内容标“AI 建议”。把访谈卡给作者看，停下来等作者确认或修改。

## 第二段：调研和选角度（第 2–3 步）

按正常流程调研，查证访谈卡里涉及的事实。作者说的事实性内容同样要核验，说错了就告诉作者，不照写。

角度方案从访谈卡出发：作者已经有核心判断时，方案 A 就围绕它写；另外的方案说明换了什么（读者、判断、切口）。在第 3 步停下，等作者选。

## 第三段：搭结构（第 5 步）◆

给出节目录：每节一个读者问题，加一句话的回答。作者表达和梳理逻辑不熟练时，结构是最需要帮忙的地方，所以要讲清排序的理由，例如“先讲网站怎么记住你，再讲多个网站怎么共用登录，因为后者建立在前者之上”。

停下来，等作者确认、调换顺序或删节。

## 第四段：逐节共写（第 6 步）

先写最难或最核心的一节，开头和结尾放到最后写：写完正文，才知道开头该怎么引、结尾该收在哪。

每一节按这个循环：

1. **列要点**：列出这一节可以写的 5–10 个点，作者说过的标“你说过”；再给 1–2 个候选的例子或类比。
2. **作者勾选**：作者可以按编号回复，例如“留 1、3、5，删 2，4 和 6 合并”；也可以直接说想法，AI 从中读出取舍。
3. **起草**：只写这一节，写进 article.md 对应位置。作者的原话尽量保留，只理顺语序、补上衔接。第一次把作者的话整理成段落时，附一组“原话 → 整理后”的对照，让作者看清改了什么；之后只在改动大时附。
4. **改稿**：请作者说要改什么，例如“第三段太绕，删掉第二个例子”，不必自己动手改。作者直接改了文件，就读一遍，把他的改法用到后面几节。
5. **收尾**：同一节连改三轮都只是小改时，问一句：“有没有哪句删掉也不影响意思？”然后进入下一节。

正文写完后写开头：给 2–3 种开头（从一件事讲起、从一个误解讲起、先给结论），用访谈卡里的开头素材，作者选一种。最后写结尾和标题。

作者嫌慢时提供加速：“剩下几节我一次写完，你再整篇看。”作者同意就照做，写完整篇停一次。

## 第五段：打磨和读者测试（第 7 步）

按 [打磨与核验](打磨与核验.md) 做四遍。读者遍里的“新读者测试”在共写模式下必须做：作者觉得清楚的地方，读者不一定看得懂。

## 记下作者的偏好

共写过程中，作者对同一类问题提了两次以上的修改（例如“别用这么多‘可能’”“例子要放在概念前面”），交付时列出来，问作者要不要写进个人写作规则，按 [风格写回](../风格/写回.md) 处理。作者没确认的不生效。
