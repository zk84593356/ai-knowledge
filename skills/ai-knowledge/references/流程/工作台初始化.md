# 内容工作台初始化

内容工作台是作者自己的文件夹，放人设、写作规则、写作技巧、平台规范、品牌资产和所有稿件（结构见 [发布合同](发布合同.md)）。Skill 只带一套默认文件，初始化时复制进工作台；以后 Skill 更新不覆盖工作台里的任何文件。

上手只有三步：初始化工作台 → 可选地建品牌资产 → 开始写。

## 什么时候做

- 用户说“在 `<路径>` 建一个内容工作台”“初始化工作台”这类话。
- 要写文章，但按 [发布合同](发布合同.md) 找不到工作台：先问一次要不要建，给出可以直接说的话，例如“在 D:\内容工作台 建一个内容工作台”。作者不建，就写到项目内的 `docs/knowledge/`，用 Skill 自带的默认文件，本次不再追问。

指定的路径已经有文件时照样可以初始化：只补缺的文件，已有的一个都不覆盖。

## 第 1 步：建工作台

路径用作者给的；没给就问，不替作者挑盘符。有 Python 时运行：

```text
python "<skill-dir>/scripts/create_project.py" init --workspace "<内容工作台>"
```

脚本做三件事：把 `templates/内容工作台/` 整套复制过去（已存在的文件跳过，并逐个列为 kept existing）；建好 `我的项目/` 下的各个子目录和空的 `品牌资产/`；把位置记到 `~/.ai-knowledge/settings.json` 的 `workspace`，以后不用再给路径。

- `settings.json` 里已经记了另一个工作台时，脚本不改，会提示。问作者要不要切换；要切换就加 `--set-default` 再跑一次。
- 作者不想记默认位置（例如只是临时建一个）时加 `--no-remember`。
- 没有 Python 时手工做同样的三件事：复制 `templates/内容工作台/` 下的全部文件，建 `我的项目/` 的子目录和 `品牌资产/`，再写 `~/.ai-knowledge/settings.json`，内容为 `{"workspace": "<内容工作台>"}`（Windows 路径用正斜杠）。

复制过去的默认文件：

| 位置 | 是什么 | 谁维护 |
| --- | --- | --- |
| `工作台说明.md` | 目录用途、三步上手、谁维护什么 | 作者 |
| `用户人设.md` | 默认人设，标着“状态：默认”，按中性作者写 | 作者改成自己的 |
| `风格参考/如何用 Grok Bot 做内容.md` | 一篇公开文章的写法拆解，示范怎么学别人的结构 | 作者可删可换 |
| `风格参考/我的写作规则.md`、`我的写作档案.md`、`改稿学习日志.md` | 个人规则的空架子 | 改稿复盘时由 AI 起草、作者确认 |
| `写作技巧/` | 内容写作技巧、金字塔原理写作技巧、偏航句用法 | 作者 |
| `规范指南/` | 自媒体防限流指南、口播引导话术、自媒体动画、运营沉淀 | 作者 |
| `品牌资产/品牌资产说明.md` | 怎么建、怎么用品牌 | 作者 |

### 可选：抓取范例原文

`如何用 Grok Bot 做内容.md` 只有写法拆解和少量摘录，原文链接写在文件开头。初始化后问作者一次要不要把原文全文存到本地。作者同意、并且你能联网读网页时：

1. 读取拆解文件开头写的原文链接，只抓这一个页面。
2. 存为同目录的 `如何用 Grok Bot 做内容-原文.md`。文件开头写标题、作者、原文链接、抓取日期，以及“仅供本人学习，不转发、不发布”。正文按原文转成 Markdown，不改写、不删减；图片只保留链接。
3. 抓不到就如实说明，拆解文件照样能用。

全文版权归原作者，只放在作者本机的工作台里，不复制进 Skill、示例或任何公开仓库。

## 第 2 步：可选，建品牌资产

问作者要不要建视觉品牌。不建也能写，配图用通用图解。一个工作台可以有多个品牌，每个是 `品牌资产/<brand-id>/`，写文章时会问用哪个（见 [品牌加载](../视觉/品牌加载.md)）。

- 作者有一张人物或角色图：按 [建立视觉品牌](../视觉/建立品牌.md) 来做。
- 作者已经有做好的品牌文件夹：整个复制到 `品牌资产/<brand-id>/`，目录名要和 `brand-kit.json` 的 `brandId` 一致，然后用 `visual_assets.py kit "<品牌目录>"` 检查。
- 作者想先占个位置：`python "<skill-dir>/scripts/create_project.py" brand <brand-id> --name "<显示名>"` 只建空目录和模板，等有图再填。

## 第 3 步：告诉作者怎么开始

交付时说清工作台位置、新建了哪些文件、保留了哪些已有文件、默认位置是否已记录，再给两三句可以直接复制的话，例如：

```text
$ai-knowledge 写一篇讲清 OAuth 和 OIDC 区别的文章，读者是刚接触统一登录的后端。
$ai-knowledge 把这篇改成小红书版本。
$ai-knowledge 复盘一下这篇我改过的稿子，学我的改稿习惯。
```

同时提醒作者先把 `用户人设.md` 改成自己的；不改也能写，只是不会用任何身份和经历。

## 从旧的个人配置目录迁移

v0.7 及更早的版本把个人配置放在 `~/.ai-knowledge/personal/`（或环境变量 `AI_KNOWLEDGE_PERSONAL` 指向的目录）。作者要求迁移时，先初始化工作台，再**复制**（不移动）下面这些内容，原目录原样保留作备份：

| 旧位置 | 新位置 |
| --- | --- |
| `writing-rules.md` | `风格参考/我的写作规则.md` |
| `writing-profile.md` | `风格参考/我的写作档案.md` |
| `learning-log.md` | `风格参考/改稿学习日志.md` |
| `visual/` | `品牌资产/<它的 brandId>/` |
| `brands/<brand-id>/` | `品牌资产/<brand-id>/` |
| `settings.json` 的 `workspace` | `~/.ai-knowledge/settings.json` 的 `workspace` |

- 目标文件还是刚复制的默认版本时，直接换成旧文件；目标已经被作者改过时停下，把两份的差别给作者看，由作者决定怎么合并。
- 旧文件里指向旧参考文档的链接（例如 `writing-craft.md`）改成新位置的文字说明，规则 ID、状态和确认依据一字不改。
- 品牌目录名和 `brandId` 不一致时，以 `brandId` 为准命名，并告诉作者。
- 迁移后跑一遍检查：`style_learning.py context` 应显示 route 为 workspace 并列出已确认规则；`visual_assets.py list` 应列出迁过来的品牌且 ok 为 true。
- 告诉作者旧目录还在、确认无误后可以自己删；不要替作者删。
