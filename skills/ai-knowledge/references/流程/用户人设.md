# 用户人设：作者是谁、写给谁、能说什么

人设决定文章用谁的口吻说话、能认领哪些身份和经历、哪些话题不碰。它放在作者内容工作台根目录的 `用户人设.md`，由作者自己维护；Skill 只读取，不替作者编写身份。

## 什么时候读

- 第 1 步接需求时读一次，用来判断读者、主发平台和作者能提供的素材。
- 第 6 步写初稿、第 7 步文字遍时回看“口吻”和“不说的话”。
- 平台改编时看对应平台的账号定位。

初始化工作台时会复制一份默认人设（文件里写着“状态：默认”）。默认人设和没有工作台时一样：按中性的第一人称作者写，只发表观点和建议，不声称任何身份、职位、年限或经历。没有工作台时读 Skill 自带的 [默认人设](../../templates/内容工作台/用户人设.md)。看到“状态：默认”时，交付时提醒作者把它改成自己的。

## 文件里有什么

| 部分 | 用途 | 写稿时怎么用 |
| --- | --- | --- |
| 我是谁 | 作者愿意公开的身份、领域和经验范围 | 只能引用这里写明的身份，不推断、不拔高 |
| 我写给谁 | 主要读者和他们的处境 | 需求卡里的读者默认取这里 |
| 账号定位 | 各平台账号分别做什么内容 | 选主发平台、决定改编版本 |
| 口吻 | 称呼读者的方式、语气、常用的表达习惯 | 写初稿和文字遍时对照 |
| 不说的话 | 作者不用的词、不碰的话题、不站的队 | 文字遍逐条检查 |
| 可公开的经历 | 作者已经允许在文章里使用的经历摘要 | 只用摘要里的事实，细节不够就去协作文档里问 |
| 代表作 | 作者认为写得好的文章 | 需要学文风时，从 `风格参考/` 里读这几篇 |

## 使用规则

- **人设只管口吻和边界，不提供事实。** “我做了八年后端”只能来自人设原文，文章里不能变成“十年”，也不能补出公司名和项目名。
- **经历只用作者给过的。** 人设里的经历是摘要；文章需要细节时按 [协作文档与真实经历](协作文档与真实经历.md) 问作者，不扩写。
- **人设和本次要求冲突时，听本次要求。** 例如作者这次要用另一个账号的口吻。
- **人设和个人写作规则分工不同。** 人设写“我是谁、写给谁”；工作台 `风格参考/我的写作规则.md` 写“我改稿时总会怎么改”，按 [风格加载](../风格/加载.md) 加载。两者冲突时，以已确认的写作规则为准，并在交付时提醒作者统一。
- **人设是私人资料。** 原文不复制进 article.md、review.md 或任何公开仓库；review.md 里只写“读取了用户人设”。

## 什么时候提议更新

改稿复盘（见 [改稿复盘](../风格/改稿复盘.md)）发现作者反复改同一类身份表述或口吻时，把建议改法写给作者，由作者决定是否改人设。Skill 不自动修改 `用户人设.md`。
