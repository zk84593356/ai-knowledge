# 资料卡：调研一次，以后还能用

资料卡把一次调研里查实的事实连同来源和有效期存下来，下次写相关主题时先查卡，不用从头搜。资料卡放在内容工作台的 `我的项目/_knowledge_base/`，格式见 [资料卡模板](../templates/资料卡-template.md)。没有工作台时不建资料卡，证据只记在 review.md。

## 一张卡记什么

一张卡回答一个具体问题，例如“OIDC 授权码流程里 state 防什么”，而不是“OIDC 资料汇总”。卡里有：

- **问题**：一句话。
- **结论**：每条结论单独一行，带证据类型和来源编号。
- **来源**：标题、URL 或文件位置、版本、访问日期。
- **有效期**：这张卡到什么时候需要重查（见下表）。
- **状态**：未核验、已核验、存疑、过期。
- **用在哪里**：引用过这张卡的文章目录。

存放路径：`_knowledge_base/<领域>/<YYYYMMDD>-<问题-slug>.md`，领域用作者习惯的中文或英文名，如 `身份认证`、`ai-tools`。

## 有效期

不同事实变化速度不同，写卡时按类型给有效期。下表是经验值，作者可以在工作台的 `规范指南/` 里改成自己的规则：

| 事实类型 | 例子 | 建议有效期 |
| --- | --- | --- |
| 价格、套餐、限额、排行榜 | AI 工具的月费、免费额度 | 30 天 |
| 产品功能和版本 | 某工具是否支持某功能 | 90 天 |
| 平台规则 | 公众号运营规范、AI 内容标识要求 | 180 天，或平台发布新公告时 |
| 标准和协议 | RFC、OIDC Core | 长期，标准更新时重查 |
| 稳定原理 | 哈希不能反推原文 | 长期 |

## 怎么复用

1. 第 2 步调研前，按领域和关键词在 `_knowledge_base/` 里找相关的卡。
2. 卡在有效期内：直接引用，证据表的依据写卡的路径和原始来源。
3. 卡已过期或状态是“存疑”：重新查原始来源，更新卡（保留旧结论并注明何时被替换），不要直接引用旧结论。
4. 卡里没有的结论照常调研，查完补进卡或新建卡。
5. 引用了某张卡，就在它的“用在哪里”追加本篇文章的目录。

## 规则

- 卡里只存可以查证的事实和来源，不存作者的私人经历、未公开的项目信息和凭据。私人代码分析的结论留在 review.md，不进资料卡。
- 写稿者自己写的卡，状态一律是“未核验”。独立复查确认后才改成“已核验”。
- 没联网时写的卡，在来源旁注明“未联网核实”。
- 资料卡不是文章素材堆：不复制大段原文，只摘必要的短句并注明出处。
