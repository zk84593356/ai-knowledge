# 个人风格的写回

个人规则保存在使用者自己的个人配置目录（查找顺序见 [风格加载](style-loading.md)），不在 Skill 安装包或源码仓库里。所以写回不需要重新安装 Skill，下次调用即生效。

## 写到哪里

只有用户本次要求"更新个人风格""写回规则"这类学习保存时才写。目标是本次实际加载的个人配置目录：

- 用户明确给出的目录，或
- 环境变量 `AI_KNOWLEDGE_PERSONAL` 指向的目录，或
- 主目录下的 `.ai-knowledge/personal/`。

写入前解析目标及其父目录的真实路径，确认就是上述目录，且不在 Skill 安装目录、当前项目的公开目录或任何 Git 仓库的跟踪范围内（个人目录本身是用户的私有仓库时除外，由用户明确说明）。有越界链接就停止写入。不扫描磁盘寻找配置，不猜测其他用户名路径。

## 怎么写

- 只改约定文件：writing-rules.md、writing-profile.md、learning-log.md。不改 visual/ 下的母版和规范，除非用户明确要求。
- 更新前比较准备方案时记录的文件散列；文件变化则重新合并，保留人工内容。
- 新规则按 [文章复盘](style-reflection.md) 的状态规则写：单篇观察是候选，用户确认才变为已确认；同义规则补证据而不重复新增。
- 个人目录不存在时，只有用户本次明确要求建档才创建最小三文件（可从 [模板](../assets/templates/writing-rules.md) 开始）；正常生成的缺失回退不得创建目录。
- 不提交、不推送；个人目录是 Git 仓库时把是否提交留给用户。

无法确定写入位置时询问用户，或直接交付待应用建议：规则 ID、目标文件、插入/替换位置、拟修改文字、基于哪个版本、学习日志条目。

## 公共规则

公共写作技法在 Skill 源码里，改它会影响所有使用者。只有在 ai-knowledge 源仓库中、且用户确认具体提案后才修改；先查现有覆盖，展示准确文字、依据与边界。源码更新后，其他项目的安装副本需要用户按原方式重新安装或更新，不能假装存在自动同步。不自动运行 skills CLI。
