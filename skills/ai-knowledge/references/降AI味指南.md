# 降 AI 味：让读者觉得有人在认真跟他说话

第 7 步文字遍时用。“AI 味”指读者读到的那种感觉：句子都对，但空、齐、没有人。去掉它的目标是读者愿意读完，不是骗过检测工具。

## 先说清楚：不以过检测为目标

- AI 检测工具并不可靠。OpenAI 2023 年 1 月发布的 AI 文本分类器，只能把 26% 的 AI 文本识别为“可能由 AI 写成”，同时把 9% 的人类文本误判为 AI，同年 7 月因准确率低下线。
- 斯坦福大学 Liang 等人 2023 年的研究发现，多款检测器把非英语母语者写的 TOEFL 作文平均 61% 误判为 AI 写作。
- 所以本指南不做“降重”、不为躲检测而替换同义词或打乱语序。这些做法会让文章更难读，平台还可能把它视为洗稿（见 [防限流指南](自媒体防限流指南.md)）。
- 文章用了 AI 辅助生成，按平台和法规要求如实标识，和文字改得好不好是两回事。

## 常见的 AI 味

维基百科编辑社区整理的 Signs of AI writing（AI 写作迹象）列出了一批典型模式。下表是它们在中文里的对应形态，加上中文写作里常见的套话：

| 模式 | 中文里的样子 | 问题 |
| --- | --- | --- |
| 意义拔高 | “这标志着……的新时代”“具有里程碑意义” | 没说具体改变了什么 |
| 宣传腔 | “强大的”“无缝的”“革命性的” | 形容词代替了事实 |
| 万能开头 | “在当今……飞速发展的时代” | 读者读三个字就知道是废话 |
| 预告和总结 | “接下来我们将介绍”“总而言之”“综上所述” | 重复，占篇幅 |
| 空过渡 | “值得注意的是”“需要指出的是” | 删掉后意思不变 |
| 否定排比 | “这不是 A，而是 B”反复出现 | 偶尔有力，处处出现就成了套路 |
| 三连排比 | 每处都列三个形容词或三个短语 | 节奏机械，第三项常常是凑的 |
| 模糊归属 | “业内专家认为”“有研究表明” | 没有来源，读者无法查证 |
| 处处总结 | 每段、每节最后一句都在总结 | 读者被反复提醒，像在读讲稿 |
| 加粗泛滥 | 一段里加粗好几处 | 什么都是重点等于没有重点 |
| 列表化 | 本该连贯讲述的内容拆成带粗体小标题的列表 | 因果关系丢了 |
| 客服腔 | “希望对你有帮助”“欢迎留言讨论” | 和正文无关的礼貌 |
| 套话 | “赋能”“闭环”“抓手”“打通” | 不一定是 AI 写的，但同样空，一并改 |

搜索这些词只用来提示回读，不机械替换。有的句子用“值得注意的是”确实是在引出一个需要注意的例外，那就留着。

## 怎么改：补具体，删空话，调节奏

改法的核心是用具体信息替换空泛表达。具体信息只能来自证据表和作者提供的素材；没有就把句子写窄或删掉，不编数字、不编经历。

下面的“改后”都是演示，方括号表示写作时要用有证据的真实内容替换：

| 改前 | 改后 |
| --- | --- |
| 在当今 AI 飞速发展的时代，代码补全工具已经成为开发者不可或缺的助手。 | 我们组 [人数] 个后端，有 [人数] 个每天在用代码补全。 |
| 这一改进显著提升了用户体验。 | 登录从输两次密码变成一次。 |
| 值得注意的是，缓存也会带来一些问题。 | 缓存的代价是旧数据：[具体现象]。 |
| 业内专家普遍认为微服务并不适合小团队。 | [具名作者] 在 [文章或演讲] 里说过，[原话或准确转述]。 |
| 该方案具有高效、稳定、易用的特点。 | 这个方案在 [测试条件] 下 [具体结果]。上手只需要改 [具体位置]。 |
| 这不是一个技术问题，而是一个管理问题。 | 代码没问题，问题出在没人负责上线前的检查。 |
| 总而言之，选择合适的工具非常重要。 | （删掉。上一段已经说清楚了。） |
| 接下来，我们将详细介绍三种常见的解决方案。 | （删掉，直接进入第一种。） |
| 希望这篇文章对你有所帮助，欢迎在评论区留言讨论。 | 如果你只能做一件事，先把 [具体检查项] 补上。 |
| 通过深入分析，我们发现问题的根源在于配置不当。 | 日志第 [行号] 行显示，[配置项] 指向了 [错误的值]。 |

## 节奏：句子有长有短

AI 文字的另一个特征是句子长度和结构太整齐。改的时候看三件事：

- **长短交替**：一个长句讲清因果，后面跟一个短句落下结论。不追求平均句长，追求有变化。
- **拆长句**：一句话超过 40 字（经验值），或者有两个以上“的”字修饰同一个名词，考虑拆开。
- **打破重复**：连续三句以上主语相同、结构相同，或者连续几段都用同样的方式开头，改掉其中一处。

最后大声读一遍，或者让朗读工具读给你听。读着拗口、换不过气、听着像念稿的地方，就是要改的地方。

## 加回“人”

AI 味淡的文章，读者能感觉到作者在场：

- **有判断**：在有依据的地方说出作者会怎么做，“如果只能做一件事，我会先……”。观点句在证据表里记为“建议”，由作者认领。
- **有取舍**：明确说哪些不讲、为什么不讲。
- **有真实细节**：作者回填的经历、截图里看到的报错、实测时意外的结果。没有就不写，不用“我们都有过这样的经历”这类假共鸣。
- **口吻一致**：按 [用户人设](用户人设-快速参考.md) 和已确认的个人写作规则，不在一篇文章里换几种语气。
