## 事实核验

研究范围：按写作者已有知识整理协议原理，并在 2026-10-16 通过网页搜索确认了 OpenID Connect Core 1.0 的发布地址；规范全文未在本次会话中逐节打开，下表条目全部未经独立复查。没有运行任何登录系统，文中的域名是 RFC 2606 保留的示例域名。

| ID | 结论 | 类型 | 依据 | 核验 |
| --- | --- | --- | --- | --- |
| F01 | 浏览器只把 Cookie 发回给设置它的站点；不同的注册域名之间不能共用 Cookie | 协议原理 | RFC 6265 第 4.1.2.3 节（Domain 属性）、第 5.3 节（存储模型） | 未核验 |
| F02 | 网站登录后发一个含随机编号的 Cookie，后续请求凭它找到用户，这就是会话 | 通用知识 | 常见的服务端会话实现方式；具体实现因框架而异 | 未核验 |
| F03 | 单点登录里网站依赖身份服务完成认证，网站不需要保存用户密码 | 协议原理 | OpenID Connect Core 1.0 第 1 节（RP 依赖 OP 认证）、第 3 节 | 未核验 |
| F04 | 身份服务的会话 Cookie 存在身份服务域名下，浏览器每次被送到身份服务都会带上它 | 通用知识 | 由 F01 推出；OIDC Core 不规定 OP 会话的具体实现 | 未核验 |
| F05 | 网站跳转身份服务时，在地址里说明自己是谁（client_id）和回到哪里（redirect_uri） | 协议原理 | OpenID Connect Core 1.0 第 3.1.2.1 节 | 未核验 |
| F06 | 身份服务会话有效时可以不再要求输入密码；会话过期时重新认证 | 协议原理 | OpenID Connect Core 1.0 第 3.1.2.3 节（OP 可使用已有会话认证用户）；prompt、max_age 参数说明 | 未核验 |
| F07 | OIDC 授权码流程中浏览器只带回一次性授权码，网站后端到令牌端点换取签名的 ID Token | 协议原理 | OpenID Connect Core 1.0 第 2 节（ID Token）、第 3.1.2.5 节、第 3.1.3 节 | 未核验 |
| F08 | SAML 的 Web 浏览器单点登录中，浏览器把签名断言带回网站 | 协议原理 | SAML 2.0 Technical Overview，Web Browser SSO Profile 与 HTTP-POST Binding 部分 | 未核验 |
| F09 | ID Token 的 aud 写着签发给哪个网站，网站必须检查 aud 包含自己的 client_id | 协议原理 | OpenID Connect Core 1.0 第 3.1.3.7 节第 3 步 | 未核验 |
| F10 | 不检查 aud 时，签发给另一个网站的令牌可以被拿来冒充用户登录 | 协议原理 | OpenID Connect Core 1.0 第 16 节安全考量（令牌替换类攻击）；由 F09 的校验目的推出 | 未核验 |
| F11 | 单点登录解决认证；权限仍由各网站自己判断 | 通用知识 | 认证与授权的通用区分；OIDC 是建立在 OAuth 2.0 之上的身份层 | 未核验 |
| F12 | 多因素认证应优先加在身份服务上 | 建议 | 由“身份服务是所有系统的共同入口”推出的作者建议 | 不适用 |
| F13 | 只退出一个网站时，只结束该网站的会话；身份服务会话仍有效时，再次登录会自动完成 | 通用知识 | 由 F04、F06 推出；OpenID Connect RP-Initiated Logout 1.0 第 1 节说明了让 OP 一同注销的需求 | 未核验 |
| F14 | OIDC 有 RP-Initiated、Front-Channel、Back-Channel 三种登出规范；浏览器限制第三方 Cookie 可能使前端通知失效 | 协议原理 | 三份 OpenID Connect 登出规范；第三方 Cookie 的影响以 Front-Channel Logout 1.0 的相关说明为准 | 存疑 |

F14 标为存疑：第三方 Cookie 对前端登出的影响随浏览器策略变化，发布前建议打开 Front-Channel Logout 规范和目标浏览器的现行策略确认措辞。

## 标题与摘要备选

| 标题 | 取向 |
| --- | --- |
| 登录一次，为什么另一个网站也认得你？ | 问题型 |
| 单点登录不是共享一个 Cookie | 反差型 |
| 拆开单点登录的那两秒：三个会话和一张写着收件人的凭证 | 结果型 |

选定：登录一次，为什么另一个网站也认得你？理由：直接说出读者每天经历但没细想过的现象，不需要任何术语就能理解；反差型标题预设读者以为是共享 Cookie，这个前提不一定成立。

摘要：单点登录没有让网站共用 Cookie，而是让每个网站都去问同一个身份服务。
