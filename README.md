# AI Knowledge

**把一个问题研究透，写成一篇读者愿意读完、作者敢署名发表的文章。**

ai-knowledge 是一个 Agent Skill，装进 Codex、Claude Code、Cursor 等支持 Agent Skills 的 AI 助手后使用。它是一套中文内容创作工作流：你给一个想法、做完的功能、想讲的知识、踩过的坑、想测的工具或想表达的观点，它先调研查证，给你几个角度选，需要你亲手实测或提供经历时列一份任务单，再写成一篇可以直接发到公众号、知乎、X 长文的文章，打磨四遍，配好封面和解释图，附上一份只给你看的发布前核验记录；需要时再改编成小红书、微博、X 短帖和短视频口播稿。当前版本 v0.7.0。

```text
   讲解              复盘                 测评               观点
 一个概念        做完的功能 / 一次故障    一个产品或 AI 工具    你的一个判断
 资料 / 链接     代码 / 日志 / 排查记录    你的实测记录          你的理由和案例
     │               │                    │                   │
     └───────────────┴─────────┬──────────┴───────────────────┘
                               ▼
  ① 接需求 → ② 调研 → ③ 选角度◆ → ④ 备素材◇ → ⑤ 搭结构 → ⑥ 写初稿
  → ⑦ 打磨四遍 → ⑧ 配图 → ⑨ 平台改编 → ⑩ 发布归档◆ → ⑪ 复盘学习
                               │
                               ▼
              你的内容工作台 / 我的项目 /
              ├── _briefs/          需求卡和角度方案
              ├── _knowledge_base/  资料卡，下次还能用
              ├── _协作文档/         需要你亲手做的任务单
              ├── 公众号写作/<日期>-<主题>/
              │   ├── article.md    可以直接发表的文章
              │   ├── review.md     只给你看的核验记录
              │   └── assets/       封面 + 2–4 张解释图
              ├── 推文写作/  短视频逐字稿/
              └── 历史存档/          发布后移入
```

◆ 是默认会停下来等你决定的地方，◇ 是需要你提供素材时才停。没有工作台时，同样的文件写在当前项目的 `docs/knowledge/<主题>/` 下。

再往上一层，它还会**学你**：

```text
   你写过的文章 ──┐
   初稿 vs 终稿 ──┼──▶ 你的写作规则 ──┐
   一句偏好     ──┘                    ├──▶ 以后每篇文章都像你写的、配图都认得出是你
   一张人物图   ────▶ 你的视觉品牌 ────┘
```

写作规则和视觉品牌都存在你自己电脑上的个人配置目录里，不进 Skill，也不进任何仓库。

## 5 分钟上手

### 1. 安装

需要 Node.js（skills 安装器要求 22.20 或更高）。Skill 本身不需要 Python、API Key 或其他依赖。

```powershell
# Codex，全局安装（所有项目可用）
npx skills add zk84593356/ai-knowledge -g -a codex -s ai-knowledge

# Claude Code / Cursor / OpenCode，把 -a 换成对应的宿主
npx skills add zk84593356/ai-knowledge -g -a claude-code -s ai-knowledge

# 以后更新
npx skills update ai-knowledge -g
```

不想用安装器，也可以把仓库里的整个 `skills/ai-knowledge/` 文件夹复制到宿主的技能目录。Codex 的用户级目录是 `~/.agents/skills/ai-knowledge/`；其他宿主以它自己的文档为准。复制时保留整个目录，不要只复制 SKILL.md。装好后重开助手或新建会话。更多安装方式和常见问题见 [安装文档](docs/installation.md)。

### 2. 写第一篇

在任意项目里打开助手，粘贴：

```text
$ai-knowledge 什么是单点登录（SSO）？面向编程初学者讲清楚，允许联网查可靠资料。
```

> `$ai-knowledge` 是 Codex 的调用写法。其他宿主可以在句首写"用 ai-knowledge Skill："，或按宿主自己的方式调用。下面所有提示词都一样。

助手调研完会给你 2–3 个角度方案，写在需求卡里。回复选哪个（也可以说“合并 A 和 B”或“都不要，换个方向”），它再接着写。不想被打断就在提示词里加一句“直接写”。

### 3. 看产物

建了内容工作台（见下一节）时，文章写在工作台的 `我的项目/公众号写作/<日期>-<主题>/` 下；没建时写在**当前项目**的 `docs/knowledge/<主题>/` 下：

- `article.md`：唯一要发表的成品，复制到平台就能用。
- `review.md`：只给你看。里面有当前进度、每条结论的依据、哪些内容出于安全考虑没写进文章、建议你补充亲身经历的位置、配图状态和备选标题。
- `assets/`：封面和解释图。
- 需求卡（`brief.md` 或 `_briefs/` 里）：读者、角度方案和你的选择。

写稿的助手不会给自己的结论盖章，所以核验记录里的条目默认都是"未核验"。发表前建议独立复查一遍，做法见下面的玩法 7。

## 建一个内容工作台

内容工作台是你放所有稿子、资料和个人写作资料的目录，和代码仓库分开。不建也能用；建了以后，需求卡、资料卡、任务单、各平台稿件和历史存档都有固定位置，资料卡下次写相关主题还能复用。

```text
$ai-knowledge 在 D:\内容工作台 建一个内容工作台，以后的文章都放这里。
```

助手会建好下面的目录，并告诉你怎样让它以后自动找到这里（设置环境变量 `AI_KNOWLEDGE_WORKSPACE`，或在个人配置目录的 `settings.json` 里写 `{"workspace": "D:/内容工作台"}`）。装了 Python 也可以自己运行 `python <Skill 安装目录>/scripts/create_project.py init --workspace "D:\内容工作台"`。

```text
D:\内容工作台\
├── 用户人设.md      # 你是谁、写给谁、能说什么，自己填，助手只读
├── 风格参考/        # 放几篇你自己数据好的文章，助手学文风时读
├── 写作技巧/        # 你自己整理的写作方法，优先于 Skill 自带的
├── 规范指南/        # 你自己更新的平台规范、口播话术、运营结论
└── 我的项目/        # 助手按流程写入：需求卡、资料卡、任务单、各平台稿件、历史存档
```

`用户人设.md` 会按 [模板](skills/ai-knowledge/templates/用户人设-template.md) 生成一份空白版，花十分钟填好，之后每篇文章的口吻和身份边界都按它来。助手不会替你补身份或经历。

## 玩法：复制就能用的提示词

方括号 `[ ]` 里的内容换成你自己的，其余原样粘贴。

### 玩法 1：把做完的功能写成文章（复盘）

在项目目录里打开助手：

```text
$ai-knowledge 把当前项目的 [登录功能] 写成一篇文章，面向 [Java 初学者]，讲清楚它是怎么设计的、为什么这样设计。
```

只想讲某一次改动：

```text
$ai-knowledge 分析从 [提交号 A] 到 [提交号 B] 的改动，写成一篇功能复盘文章，讲清改了什么、为什么改、踩了什么坑。
```

助手会读相关的代码、配置和测试，把每个项目事实对应到文件和行号，记在 review.md 里。公司名、内部域名、类名和私有代码不会进文章；需要代码时，它会重写一段原创演示。

### 玩法 2：讲清一个知识（讲解）

```text
$ai-knowledge 什么是 [OAuth 2.0]？面向 [刚入门的后端]，允许联网查官方文档和标准。
```

把你看过的资料一起交给它：

```text
$ai-knowledge 根据这几份资料讲清楚 [向量数据库是什么]，资料之间有冲突的地方要指出来：
[网页链接 1]
[网页链接 2]
[本地 PDF 或 Markdown 文件路径]
```

看完一个视频想整理成文章（先导出字幕或文字稿，助手不能直接看视频）：

```text
$ai-knowledge 这是一个视频的文字稿，帮我整理成一篇讲清 [主题] 的文章。文字稿里的观点要和权威资料核对，不能确认的写窄或标出来：
[粘贴文字稿，或给出文件路径]
```

非技术主题也可以：

```text
$ai-knowledge 什么是 [机会成本]？面向普通读者，用 [选择学习时间] 的例子解释，短一点，不需要代码。
```

### 玩法 3：复盘一次踩坑（复盘）

```text
$ai-knowledge 帮我复盘这次 [部署失败]。只根据我提供的材料，区分事实和推测，没解决的部分写成阶段性复盘：
[粘贴报错和日志]
[粘贴或附上排查时的聊天记录、截图]
```

日志原文只留在 review.md，文章里写整理后的现象。助手不会把建议写成已经做过的操作，也不会把"可能是这个原因"写成定论。

### 玩法 4：测评一个产品或 AI 工具（测评）

```text
$ai-knowledge 我想测评 [工具 A] 和 [工具 B] 的 [代码补全]，读者是 [要做选型的后端组长]。先帮我设计测试，写一份我照着做的协作文档。
```

助手会定好对象、版本、对照组和判断标准，把统一提示词、步骤和记录表写进 `_协作文档/`。你照着跑、照着填（每个任务建议跑 3 次），然后说：

```text
$ai-knowledge 协作文档填好了，[跳过了 T3]，按记录写测评。
```

文章里的实测结论只来自你填的记录；你没填的项不会出现在文章里。有赞助、返佣链接或其他利益关系时告诉它，它会在文中显著说明。

### 玩法 5：讲清一个判断（观点）

```text
$ai-knowledge 我的观点是 [三个人以下的团队别自建 Kubernetes]，理由是 [你的两三条理由]。帮我写成一篇观点文章，认真回应反方。
```

助手会把事实和判断分开：事实去查证，判断写成你的主张；用反方自己认可的方式复述反方，再说分歧在哪；写明这个判断在什么情况下不成立。

### 玩法 6：先出选题，调整协作方式

只想先要几个方向：

```text
$ai-knowledge 我想写 [AI 编程工具] 相关的内容，读者是 [刚开始用 AI 写代码的后端]。先调研，给我 3 个角度方案，不要动笔。
```

协作强度有三档：快速（不停下来，助手自选角度并写明理由）、标准（默认，选角度时停一次）、深度（角度、结构、初稿各停一次）。其他常用调整：

```text
$ai-knowledge 什么是 [SSO]？直接写，不用等我选角度。
$ai-knowledge 什么是 [SSO]？这篇很重要，用深度协作。
$ai-knowledge 什么是 [SSO]？面向有两年经验的后端，展开讲，不要图。
$ai-knowledge Explain [SSO] for beginners in English. Put the files in ./learning/sso.
$ai-knowledge 什么是 [SSO]？配图不用我的个人品牌，用通用图解。
$ai-knowledge 什么是 [SSO]？只用公共写作规则，不用我的个人风格。
```

协作强度只改变停下来的次数，查证和隐私要求不变。

### 玩法 7：发表前把关和归档

下面的 `[项目目录]` 是文章所在的目录，例如 `D:\内容工作台\我的项目\公众号写作\20261017-sso` 或 `docs/knowledge/sso`。

换一个新会话独立复查（写稿的那个会话不适合复查自己）：

```text
$ai-knowledge 请独立复查 [项目目录]/review.md 的事实核验，逐条对照依据，更新核验状态，列出需要我处理的问题。
```

补一段自己的真实经历（review.md 里列出了最适合放经历的位置和建议问题）：

```text
$ai-knowledge 我补充一段亲身经历：[你的经历]。请把它写进 [项目目录]/article.md 的 [第二节]，其余内容不动。
```

确认可以发了，发完再告诉它：

```text
$ai-knowledge [项目目录] 这篇可以发布了。
$ai-knowledge [项目目录] 已经发到公众号了，链接是 [URL]，帮我归档。
```

助手不会替你编造经历，也不会替你发布。只有你明确说可以发布，review.md 的状态才会改为 ready；你说已经发布后，它记下平台和链接，把项目移进 `历史存档/`。

### 玩法 8：一稿多发和短视频口播

公众号、知乎、掘金、X 长文直接用 article.md。其他平台另写一份改编稿，主稿不动：

```text
$ai-knowledge 把 [项目目录]/article.md 改编成小红书版本：3–9 张竖版图，每张一个要点，配一段短文案。
$ai-knowledge 给 [项目目录]/article.md 写一条微博，只放一个最有冲击力的结论和一张图，引导读者看长文。
$ai-knowledge 把 [项目目录]/article.md 改成一条 [90 秒] 的短视频口播稿，写清每段的画面和动效。
```

改编稿放在工作台的 `推文写作/` 和 `短视频逐字稿/`（没有工作台时放在主稿旁边）。助手会按平台规则检查标题、互动引导、站外导流和 AI 内容标识，结果写进 review.md。

### 玩法 9：更新一篇旧文章

```text
$ai-knowledge 更新 [项目目录] 这篇文章：[框架升级到了新版本 / 我发现第三节有个错误]。在原目录修改，保留创建日期，在 review.md 里记下改了什么。
```

不说"更新"或"改这篇"时，同名主题会在旁边新建一个带编号后缀的目录，旧文件保持原样。

### 玩法 10：让文章越写越像你

**从你写过的文章里提炼风格：**

```text
$ai-knowledge 分析这几篇我自己写的文章，提炼我的写作风格：句子长短、常用词、怎么过渡、怎么开头和结尾，每条都附上证据和例外。提炼出的规则先作为候选写进我的个人配置目录，我确认后再生效。
[文章文件路径，或一个 ZIP]
```

**直接说出你的偏好：**

```text
$ai-knowledge 更新我的写作规则：不要用"赋能""抓手""闭环"这类词；段落不超过 4 句；结尾不写"希望对你有帮助"。这些是我明确的偏好，直接记为已确认。
```

**从你的修改里学习（最准的方式）：**

```text
$ai-knowledge 对比 [初稿路径] 和我改好的终稿 [终稿路径]，总结我的修改习惯，更新我的个人风格。
```

**看看现在记住了什么：**

```text
$ai-knowledge 列出我个人配置目录里已确认和候选的写作规则，各用一句话说明。
```

单篇文章里观察到的习惯先记为候选，你确认后才生效；你直接说出的偏好可以立即确认。规则写回你的个人配置目录，下次调用就生效，不用重装 Skill。别人的文章只能提炼成可借鉴的技巧，不会被当成"你的习惯"。

**用发布数据指导下一篇：**

```text
$ai-knowledge 这是 [项目目录] 发布 7 天的后台数据：[阅读人数、分享、收藏……]。记下来，和之前同类文章比一比，有结论就写成候选给我看。
```

单篇数据只能得出候选结论，同类文章积累多了才看趋势；结论经你确认后写回选题库或写作规则。

### 玩法 11：给文章配上你的品牌人物

建好品牌以后（见下一节），写文章时默认就会用它配图。也可以点名指定：

```text
$ai-knowledge 什么是 [SSO]？用 [blue-cat] 品牌配图。
$ai-knowledge 什么是 [SSO]？封面复用 [desktop-work] 场景图，不要重新生成。
```

## 打造你的专属品牌人物

一个好的品牌人物能让读者不看名字也认得出你的文章。第 0 步在 Skill 外准备人物图，之后每一步用一句话启动，第 2、3 步可以跳过。

### 第 0 步：准备一张原创人物图

这一步不需要 Skill，你可以自己画、找人约稿，或者用任何 AI 生图工具生成。用 AI 生成时可以粘贴下面这段：

```text
帮我设计一个原创的 2D Q 版角色，作为我的个人品牌形象，用在技术文章配图和视频里。
- 性格关键词：[好奇、认真、有点呆萌]
- 识别点（2–3 个，越独特越好）：[一撮翘起来的头发、竖条形的眼睛、一条蓝色围巾]
- 主色（只选一个，以后会成为品牌色）：[蓝色 #4292EC]
- 画法：干净的 2D 平涂、深色描边、大头短身
- 画面：全身正面站姿，纯白背景，不要任何文字
不要模仿任何已有的动漫、游戏或品牌角色。
```

好的品牌人物有三个特点：识别点少而鲜明；主色只有一个；剪影简单，缩成头像也认得出。别用知名 IP 或别人的角色，否则授权状态只能是"待确认"。用真人照片时，只能是你本人，并且你同意。

### 第 1 步：用这张图建立品牌

把图片发给助手（附件或文件路径），**并且明确说要建立品牌**：

```text
$ai-knowledge 用这张图建立我的视觉品牌。
```

它会一次问你三个问题，每个都可以跳过：

```text
名字：小蓝，ID 用 blue-cat
来源：我用 [某某工具] 生成的
用途：文章和视频都要
```

助手会在个人配置目录的 `brands/blue-cat/` 生成一套草稿：原图原样保存，写好角色规范、风格规范、来源说明和程序要读的 `brand-kit.json`。只发图不说要做什么，或者写文章时附带了截图，都不会启动这个流程。

### 第 2 步（可选）：生成三视图和场景图

```text
$ai-knowledge 给 blue-cat 生成三视图（正面、侧面、背面）和 3 张场景候选：讲解、敲电脑、思考，其中一张是 16:9。先放进候选让我挑。
```

这一步需要宿主带有**能接收参考图**的生图工具，例如 Codex 的生图功能。没有这类工具时，助手只写好提示词，不会假装锁定了角色。生成的图先放在 `candidates/` 里，你挑中的才会登记。

### 第 3 步（可选）：定视觉语言，做四图测试

这一步决定你的配图"好不好看、像不像一套"：

```text
$ai-knowledge 给 blue-cat 起草视觉语言：提 2–3 个材质比喻让我挑，线条颜色取角色描边，主色取角色身上最醒目的颜色，从角色识别点里提取 2–3 个签名图形。然后用"[一个你熟悉的主题]"做一次四图测试：封面、流程图、数据图、插画各一张，拼成一张对比图给我看。
```

方法见 [美术方向](skills/ai-knowledge/references/视觉-美术方向.md)：一个材质比喻、一支笔、一个只当工具用的主色、从角色身上提取的签名图形、固定的页眉页脚、角色当讲解员、字少字大、生图有规矩、整组验收。不满意就直接说哪张、哪里不行，助手改完重做，直到你满意：

```text
$ai-knowledge 四图测试里封面不够亮眼，人物太小；流程图字太多。按这个意见重做这两张，其余不动。
```

满意以后，这组图可以登记为风格样板，以后出图时当风格参考：

```text
$ai-knowledge 四图测试我满意，把这组图登记为 blue-cat 的风格样板。
```

### 第 4 步：确认，正式生效

检查 `character.md` 里写的识别点和颜色没问题后：

```text
$ai-knowledge 确认 blue-cat，配色也确认。
```

确认后，如果你还没有默认品牌，它会自动成为默认品牌：以后写文章不用点名，配图自动用它。如果已经有默认品牌，助手会先问你要不要替换。

### 第 5 步：以后慢慢补

```text
$ai-knowledge 给我的默认品牌加一张场景图：角色抱着笔记本电脑思考，16:9。先放候选给我挑。
$ai-knowledge 列出我所有的视觉品牌和它们的状态。
```

## 个人配置放在哪里才生效

所有个人内容都放在这个目录里。安装、更新、卸载 Skill 都不会碰它：

```text
~/.ai-knowledge/personal/            # Windows：%USERPROFILE%\.ai-knowledge\personal\
├── writing-rules.md                 # 写作规则：只有"已确认"的条目生效
├── writing-profile.md               # 规则适用的范围
├── learning-log.md                  # 学习记录
├── visual/                          # 默认视觉品牌：确认过的品牌放这里，写文章自动使用
│   ├── brand-kit.json               #   程序入口：状态、配色、素材清单
│   ├── character.md                 #   角色识别点、颜色、生图提示词、验收清单
│   ├── style.md                     #   定位、配色、视觉语言、各类图的做法、风格样板
│   ├── provenance.md                #   来源、授权、版本记录
│   ├── assets/
│   │   ├── canonical/               #   母版：原图、三视图、细节图
│   │   ├── scenes/                  #   场景图
│   │   └── samples/                 #   风格样板
│   └── candidates/                  #   还没选中的候选，不会被使用
└── brands/<brand-id>/               # 其他品牌，结构和 visual/ 一样；写文章时说"用 <brand-id> 品牌"
```

**生效规则：**

1. 助手按这个顺序找个人配置目录：你在请求里给出的路径 → 环境变量 `AI_KNOWLEDGE_PERSONAL` → 上面的默认位置。
2. 默认位置 `visual/` 里的品牌，只有状态是"已确认"才会自动使用；草稿品牌只在你点名时使用。
3. `brands/<brand-id>/` 里的品牌不会自动使用，要点名。
4. 什么都没有时，用公共写作技法和通用图解，功能完整。

上面的流程会帮你建好这些文件，一般不用手动操作。想手动建一个品牌，可以从 [品牌模板](skills/ai-knowledge/templates/brand/) 复制四个文件，填好后用检查工具确认（需要 Python 3.10+）：

```powershell
python <Skill 安装目录>/scripts/visual_assets.py inspect <品牌目录>   # 读出图片尺寸和校验值，用来填 brand-kit.json
python <Skill 安装目录>/scripts/visual_assets.py kit <品牌目录>       # 检查整套品牌，ok 为 true 才算建好
python <Skill 安装目录>/scripts/visual_assets.py list                 # 列出所有品牌和状态
```

格式可以参考测试用的 [演示配置](tests/fixtures/personal-demo/)。

**多台电脑共用一套配置：** 把个人目录放进一个私有 Git 仓库，在每台电脑上克隆，再设置环境变量指过去，重开终端和助手后生效：

```powershell
[Environment]::SetEnvironmentVariable('AI_KNOWLEDGE_PERSONAL', 'D:\private\my-personal', 'User')
```

不要把个人目录放进 Skill 的安装目录或任何公开仓库。

## 它怎样写一篇文章

| 步骤 | 做什么 | 产物 |
| --- | --- | --- |
| ① 接需求 | 判断内容类型，读你的用户人设，补齐读者、平台和协作强度 | 需求卡 |
| ② 调研 | 先查资料卡，再按类型读代码、资料、记录或查公开来源，每条结论标出类型和依据 | 证据表、资料卡 |
| ③ 选角度 ◆ | 2–3 个取向不同的方案：核心判断、写给谁、标题、结构、需要你提供什么 | 需求卡里的角度方案 |
| ④ 备素材 ◇ | 需要实测、截图或经历时，列一份你照着做的任务单 | 协作文档 |
| ⑤ 搭结构 | 结论先行，每节回答读者的一个问题，一个例子贯穿全文 | 提纲 |
| ⑥ 写初稿 | 用写作技巧、你确认过的规则和工作台的文风样板写正文 | article.md |
| ⑦ 打磨四遍 | 事实遍、读者遍、文字遍（降 AI 味、查平台规则），最后独立复查 | 修订后的 article.md |
| ⑧ 配图 | 封面 + 解释图，每张只回答一个问题，手机宽度下可读，整组风格统一 | assets/ 与 manifest.json |
| ⑨ 平台改编 | 你要求时，按小红书、微博、X、短视频的读法重新组织 | 推文写作/、短视频逐字稿/ |
| ⑩ 发布归档 ◆ | 报告路径、未核验条目、任务完成情况；你说发了才归档 | review.md、历史存档/ |
| ⑪ 复盘学习 | 你给发布数据或改好的终稿时，总结规律，经你确认写回 | 选题库、写作规则 |

三条原则贯穿全程：

- **判断可以有立场，经历必须真实。** 你没讲过的经历不会被写成第一人称故事，而是在 review.md 里留出位置和建议问题。
- **不确定性写在原地。** 证据不足就把结论写窄，不在文末堆免责声明。
- **公开安全优先。** 公司、内部域名和类名、日志原文、尚未修复的问题都留在 review.md；文章里放重写的原创演示。

## 能做什么、不能做什么

- 文章质量取决于你用的助手、模型和工具。Skill 是一套写作和审核的方法，不是独立程序。
- 联网查证、读 PDF、看图、生图都依赖宿主的能力。不能联网时，review.md 会写明"未联网核实"；没有生图工具时，助手会用程序画解释图，人物图记为待制作。
- 不能直接看视频，需要先导出字幕或文字稿。
- 生成图里的中文和数据比例会逐项核对，但最终好不好看只有你能判断。
- 不会自动发布、提交或推送；不改业务代码。
- 自动检查只能证明文件结构和图片台账一致，不能证明事实正确或内容可以公开。所以发表前请做一次独立复查（玩法 7）。
- 平台规则整理到 2026-10-17，会过时；助手会提醒你发布前核对平台当前规定。“限流”的各种传言没有官方依据，不会被当成规则。
- 目前只在 Codex 里完整跑过；Claude Code、Cursor、OpenCode 可以安装，但没有完整实测。
