# 真实 Java OIDC 项目｜Feature 模式验收方案

日期：2026-10-15，2026-10-16 按 v0.4.0 文件合同（article.md + review.md + assets/）更新。状态：可执行方案，尚未获得真实业务项目路径或源码，未开展业务代码分析、构建或登录测试。公开仓库只保存本通用方案；真实源码、私有证据、测试日志与全部生成产物默认保留在该业务项目中。现有 Python oidc-demo 仅是原创演示，不能代替真实 Java 项目验收。

## 1. 确定范围和输出边界

执行前提供：项目真实路径、功能目标或入口、当前实现或明确 Commit/比较范围、读者及输出位置。测试环境/测试账号仅在需要联调时由安全渠道提供，不贴到公开任务、文档或命令参数。先确认分析对象是 OIDC 登录客户端、资源服务器还是身份提供方，不能见到 JWT 就当 OIDC 登录。

读取项目 AGENTS 与 README，记录 HEAD、工作区是否有改动、JDK、构建工具及依赖版本。只读使用 Git；两端树差异与 merge-base 比较明确区分，不改 checkout、不重置工作区。初始只做源码和测试定义的静态阅读，业务代码、配置与数据库不改。

默认写入该业务项目的 docs/knowledge/oidc-login/，article.md、review.md 与 assets 同属此目录；已存在则按 Skill 日期/序号规则新建同级目录。解析实际绝对路径和符号链接，确认不在 ai-knowledge 或全局 Skill 安装目录。写入知识产物不等于允许修改业务代码、执行构建或连接生产系统。

开始前检查该输出目录是否会被业务项目既有发布流程或 Git 跟踪；需要忽略时提出该项目内的具体建议，不擅自改全局忽略规则。日志与敏感证据按最小量保存；默认也不自动提交业务仓库。

## 2. 最小代码分析范围

先按功能定位，再沿调用链扩展，避免全仓倾倒。下列符号只是定位关键词，不预先宣称项目中存在。

| 范围 | 读取与定位 | 要形成的证据 |
| --- | --- | --- |
| 构建与版本 | pom.xml、build.gradle(.kts)、wrapper 属性、依赖管理；不读私有仓库凭据 | JDK / Spring Boot / Spring Security 或其他 OIDC 库的实际解析版本，直接/传递依赖差别 |
| 安全入口 | Servlet SecurityFilterChain 或 WebFlux SecurityWebFilterChain；oauth2Login、路径匹配器、多个链的顺序 | 哪些请求触发登录，哪些公开，哪些受保护；不能套用另一技术栈默认行为 |
| 客户端配置 | registration/provider、issuer、redirect-uri、scope、client authentication method | 只记录键名、来源与脱敏关系；不展开 secret 或读取 .env、密钥库、私钥 |
| 授权请求与回调 | resolver、authorization request repository、callback/filter/handler、token client | state / nonce / PKCE 的生成、绑定、持有、验证与失败路径由谁完成 |
| 令牌验证 | decoder、validator、JWK/issuer 配置、框架版本依据及定制点 | 签名/允许算法、iss、aud、适用时 azp、时间及 nonce 检查；区分框架行为与本地代码 |
| 用户与授权 | OidcUserService / claims mapper、账户关联、权限映射 | 外部身份到本地用户的映射；登录不等于业务授权，不把 email 无条件当稳定全局 ID |
| 会话与退出 | SecurityContext、session strategy、Cookie 配置、logout handlers | 应用会话生命周期、会话固定防护证据、Cookie 属性、退出影响范围 |
| 测试与运行资料 | 相关 unit/integration tests、已授权且脱敏的日志/截图 | 哪些是 mock、哪些实际验证协议/签名、哪些真实 IdP 联调；不顺手采集生产流量 |

证据表写进业务项目内的 review.md“事实核验”，表头固定为 `| ID | 结论 | 类型 | 依据 | 核验 |`；依据写路径/类/方法、行号或 Commit。类型用 Skill 的六类（项目事实、框架行为、协议原理、通用知识、推测、建议），写稿者自己写的结论一律“未核验”。缺实现或框架版本证据时标待核实；不把标准要求写成项目已经做到。设计动机需设计文档或作者说明，不能从代码替作者编故事。

## 3. 知识输出合同

| 产物 | 内容与验收点 |
| --- | --- |
| article.md | 唯一要发表的文章：一句话核心判断、一个贯穿全文的具体场景、每节回答一个读者问题；默认公共技法 + 个人配置目录中的有效写作规则；不复制私有代码、内部地址或截图，必要代码重写成原创演示；正文不含状态、核验日期等生产信息 |
| review.md | 发布状态（draft）、事实核验证据表、公开安全过滤（只写类别与替代写法，不复述原值）、可补充的个人经历位置、配图状态、标题与摘要备选 |
| assets/ 与 manifest.json | 封面 + 2–4 张解释图的 PNG 与可编辑 SVG；来源、状态、实际尺寸/散列；未生成的图不插链接 |
| 验收记录 | 实际命令、版本、通过/失败/跳过、未验证事项、脱敏复核、用户批准依据；留在业务项目内，不写进 article.md |

两份文件共享 topic、mode（feature）、language 和真实日期，type 分别为 article 与 review，字段见 Skill 的 publishing.md。缺证据可交付明确受限的文章（结论写窄），但不能宣称完整通过真实 OIDC 验收。用户没有提供开发经历时，在 review.md 留出位置和问题，不虚构开发过程。

## 4. 配图规划

v0.4.0 默认配封面和 2–4 张解释图。先核实事实再选图，以下是候选而非强制配齐；文章里只嵌 PNG，Mermaid 只能作为制作手段，导出成图片后再用：

| 位置/问题 | 候选图 | 制作/材料 | 验收重点 |
| --- | --- | --- | --- |
| 首次机制解释：谁信任谁 | 浏览器 / Java 应用 / IdP 关系图 | Mermaid 或可编辑 SVG；项目证据表 | 标清认证来源与应用会话，不能画应用直接共享 Cookie |
| 实现细节：一次登录如何走完 | 授权码登录时序与失败分支 | 实际参与者与回调/交换/验证证据；省略处注明 | 前通道与后通道分开；错误分支不继续画成功建会话 |
| 易混淆：令牌用在哪里 | 2–4 列小表格或少量标签图 | 项目实际令牌用途 | ID Token / Access Token 区别；不把所有 Access Token 默认成 JWT |
| 真正需要界面说明时 | 已授权真实测试截图 | 脱敏后的截图副本 | 无 Token、账户标识、内部域名；无素材就不制作假 UI |
| 封面/缓冲/署名 | 可选通用图解或个人配置目录中的品牌资产 | 已有合法使用依据；权利不明时保留计划或不用人物 | 角色不漂移；公共再分发尚待确认的素材不当成公开授权 |

未批准的 BKC 提案不作为已生效强制规范；上述只是本次方案的设计选择。技术图优先本地渲染，不向外部生图/在线 Mermaid 服务发送私有代码或业务关系。确需外部图像工具时仅使用已获准、无敏感信息的通用提示与参考素材。

图中文字可编辑，复杂中文用程序化方案；目标平台要求 PNG 时真实导出并保留源。按实际正文宽度及 390px 容器检查，记录内边距；检查字体实际命中、文字碰撞、箭头、等价正文、alt、相对链接、尺寸/hash与迁移。工具缺失就记录未验证；所有新图默认 draft/generated，审批和权利状态分别记录。

## 5. 隐私与发布隔离

只读取有关模块，跳过 secrets、私钥/keystore、生产配置值和无关客户数据。发现敏感内容只报告类别与本地位置，不回显原值。对域名、租户、账号、email、client ID、内部路径和业务名称使用一致的虚构别名，例如 app.example.test / idp.example.test；映射表如确有必要仅保留在业务项目的受控位置。

Token、Cookie、Authorization、授权码、client secret、会话 ID 不保留原值，也不通过只裁剪中间部分假装脱敏。截图使用不可逆脱敏后的扁平副本，检查隐藏图层、SVG 文本/注释/base64、EXIF、文件名、链接与日志附件。保留真实机制与字段名，不能脱敏到改变结论。

文章必须单独人工复核；“存在 article.md”不代表已经允许发布，review.md 的 status 由用户明确确认后才改为 ready。真实业务代码和产物不复制到本仓库的 examples、tests/fixtures、临时文件或附件；不上传到公开 Issue/PR。未来如要共享经验，另行明确授权后，仅考虑独立重写的通用材料并重新验收。

## 6. 分层执行与负向验收

先审阅构建脚本、wrapper、插件与测试连接配置，再决定可运行命令；构建可能下载依赖、执行插件或连接数据库，不能把“测试”当成无副作用。仅在获准的隔离测试环境使用测试身份提供方与账号，生产环境不自动操作。确认具体模块和任务后选择 Maven 或 Gradle，不能同时盲跑全仓集成测试。

~~~text
# 以下是执行时替换参数的示意，不是本轮已运行命令
mvnw.cmd -pl <module> -Dtest=<confirmed-test-class> test
gradlew.bat :<module>:test --tests <confirmed-test-class>
~~~

| 层级/场景 | 需要的观察或断言 | 结论边界 |
| --- | --- | --- |
| 静态链路 | 配置→请求→回调→验证→用户映射→会话，来源可定位 | 代码出现检查逻辑不等于运行成功 |
| 授权响应绑定 | 缺失/错 state、重放回调、另一浏览器会话、拒绝授权 | 失败不创建登录态；记录实际路径而非仅验证测试桩 |
| ID Token 校验 | 错签名/不允许算法、错误 issuer/audience、过期、适用时 nonce/azp | 使用测试签名/JWK 或真实库验证；mock principal 测试不证明验签 |
| PKCE（按客户端与流程评估） | 使用时检查 S256、请求绑定和错误 verifier 被拒绝 | 客户端单测不冒称测试过 IdP 侧拒绝；未启用时记录风险/依据，不假定框架默认开启 |
| 身份与授权 | 账户关联、缺必要 claim、无角色访问受限资源 | 已登录但无权限仍被拒绝，异常不遗留登录态 |
| 会话与退出 | 应用会话更新/失效、Cookie 配置、退出后访问 | 本地退出不自动等于 IdP 或所有应用全局退出 |
| 可选真实联调 | 授权的非生产 IdP 完成登录与一个受保护请求；再测必要失败路径 | 无环境时记未执行；单应用登录不能证明跨应用 SSO，需第二应用独立验证 |
| 文章/核验记录/图片 | 内容证据、文件合同、脱敏、渲染、路径、状态 | 机器通过不能代替事实/审美/公开许可 |

会话过期、IdP 不可用、JWKS 获取/轮换失败、回调错误与权限不足，根据项目实际支持路径补充；不为凑矩阵伪造未实现功能。每项记录通过、失败、未执行或不适用及理由。无需为了写知识文档修改业务实现；发现问题作为证据明确的改进建议。

可使用本地开发检查器；Skill 使用本身不要求安装 Python：

~~~text
python <ai-knowledge-source>/tests/validate.py --bundle <business-topic-directory>
python <installed-skill>/scripts/visual_assets.py bundle <business-topic-directory> --brand <chosen-brand-directory>
~~~

第二条在有配图时执行（用户说“不要图”则跳过）；这些只读检查不移动或上传产物。Mermaid/截图渲染工具也在业务项目的本地测试目录输出，不拿本公开仓库作为私有素材中转站。

## 7. 通过条件与交付

- 关键项目结论都有文件/符号/版本依据；未核实与建议明确区分，所有失败/未执行如实记录。
- article.md 与 review.md 文件名、元数据和事实边界一致；文章可直接复制到平台，自然易读且无未经授权的私有信息；证据表的每个影响结论的句子都能对上一行，并由新会话、子 Agent 或用户独立复查。
- 图表节点与箭头能逐项映射证据，条件在正文可读；图片实际存在、自包含或有实际 PNG、相对路径与台账一致。
- 独立报告工程检查、内容审读、用户审美和授权状态；未批准图不升 approved。真实联调未执行就只能完成静态/内容阶段，不能称真实集成通过。
- 交付业务项目内 article.md、review.md、assets/ 和验收报告路径；核对业务源文件未改，ai-knowledge 仓库没有新增业务数据。默认不 Commit/Push、不发布、不全局安装。

启动顺序：提供项目路径与范围 → 只读定位证据 → 确认可运行的测试范围 → 立意与提纲 → 在业务项目写 article.md → 配图 → 编辑三遍并填写 review.md → 脱敏/合同/渲染检查 → 分层报告与用户验收。源码还未提供时只停留在本方案，不要求把私有源码上传公开仓库。

## 官方参考与版本边界

2026-10-15 已查看 [OIDC Core](https://openid.net/specs/openid-connect-core-1_0.html) 的授权码流程与 ID Token 校验，以及 [OAuth 安全实践 RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html) 的请求绑定/PKCE 相关指导。它们用于设计待核实项，不证明目标项目已经实现。

若项目采用 Spring Security，可从 [OAuth2 Login 配置文档](https://docs.spring.io/spring-security/reference/servlet/oauth2/login/core.html) 定位配置与组件；执行时必须选与实际依赖一致的版本文档/源码。当前网页不是未知项目版本的证据；非 Spring 或响应式项目按其实际栈调整范围。
